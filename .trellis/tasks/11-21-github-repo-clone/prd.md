# GitHub、云端缓存和 ZIP 分享

## 目标

用户从主列表管理本地项目和云端项目。
用户可选择 GitHub 仓库并克隆。
用户可分享文件、文件夹和项目。

## 需求

- R1：同时支持 OAuth 和 PAT。默认使用 OAuth。
- R1：列出凭据可访问的全部仓库。支持分页和多选。
- R2：新克隆写入默认项目目录的 `gitProjects/`。
- R2：已有项目保留原路径。目录冲突不得覆盖文件。
- R3：主项目列表支持删除云端项目。
- R3：删除失败时保留项目卡片和缓存。
- R4：文件树长按菜单支持文件和文件夹 ZIP 分享。
- R5：主页本地项目支持导出后调用系统分享。
- R6：云端文件和项目同样支持导出分享。
- R7：云端缓存位于默认项目目录的 `cloudProjects/`。
- R7：缓存按服务地址、账号和项目 ID 隔离。
- R8：主列表显示未缓存、缓存中、已缓存和同步失败。
- R8：显示缓存时间、文件数和大小。
- R8：提供缓存、更新缓存和清理缓存操作。
- 每个需求独立提交。提交记录标明需求编号。

## 约束

- 分享前更新云端缓存。下载完整后才打包。
- 缓存保留未上传的本地修改。
- 清理缓存与删除云端项目分别确认。
- 取消分享不删除项目或源文件。
- 令牌只写入系统安全存储。
- 令牌不得进入日志、仓库地址或项目文件。
- GitHub 令牌不得发送到 QFLI 或 Relay。
- 单个克隆失败不阻止其他克隆。
- 注册失败时保留下载文件。
- 本地只运行格式检查和静态分析。
- 测试与构建交给云端 CI。

## 验收

- [ ] OAuth 与 PAT 均能读取全部授权仓库。
- [ ] 多选仓库进入独立克隆任务。
- [ ] 新克隆均位于 `projects/gitProjects/`。
- [ ] 云端项目可从主列表删除。
- [ ] 旧刷新结果不会恢复已删除项目。
- [ ] 文件树可分享文件和文件夹 ZIP。
- [ ] 主页可导出并分享本地项目和云端项目。
- [ ] 缓存路径位于 `projects/cloudProjects/`。
- [ ] 部分下载不会标记为已缓存。
- [ ] 清理缓存不会删除云端数据。
- [ ] 不同账号的缓存互相隔离。
- [ ] 每个需求对应独立提交记录。

## 范围外

- 自动迁移已有 Git 克隆目录。
- 创建 GitHub 仓库或推送代码。
- 自动发布安装包或部署服务。
