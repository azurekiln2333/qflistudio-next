# Agents desktop 形态重构：跨平台 harness + 响应式工作台 + CI/CD

## Goal

Studio 采用桌面端 agents 应用的形态。
全部平台的体验统一，不割裂。

## Requirements

- R1 主页：用户在主页创建项目，然后进入项目。
- R2 项目页：进入项目后显示该项目的 agent 会话列表。底部显示输入卡片。用户点击会话后进入对话流。
- R3 输入卡片：卡片是长方形。上方是输入区。下方是工具行。发送按钮在卡片内部。
  - 工具行包含加号。加号添加项目内文件或工作区文件。
  - 工具行包含权限模式选择。
  - 工具行包含模型选择。
  - 工具行包含推理强度选择。
- R4 侧边栏：侧边栏支持 AI 会话列表和文件列表切换。
- R5 窄屏（手机）：主体区域支持编辑器和 agent 对话流切换。
- R6 宽屏（Windows、macOS 等可拉伸窗口）：左侧是侧边栏（同 R4）。中间是编辑器。右侧是 agent 对话流。用户可以收起和展开对话流。
- R7 跨平台 agent harness：各平台使用同一套 agent 循环和工具。harness 支持 skill。
- R8 登录门控：所有 agent 功能在登录后才能使用。
- R9 其他逻辑与现状保持一致。
- R10 CI/CD：core 和 studio 两个仓库实现跨仓库云构建。CI 发布 APK release。
- R11 移动端系统权限：确认各平台的限制。每个受限工具有降级方案。

## Constraints

- 工作区有用户未提交的改动。任何人不得执行破坏性 git 命令。
- 提交信息使用 Conventional Commits。提交信息不带 AI 署名。
- 交互以人性化为第一标准：同一操作在各平台的入口位置一致。

## Acceptance Criteria

- [ ] 未登录用户触发 agent 功能时，应用引导登录，不崩溃。
- [ ] 窄屏和宽屏使用同一套状态。用户拉伸窗口跨越断点时，会话和编辑器内容不丢失。
- [ ] 输入卡片满足 R3 的全部元素。
- [ ] agent 在每个支持的平台能读、写、搜索工作区文件。
- [ ] 项目级 skill 能被发现、加载、调用。
- [ ] `flutter analyze` 无新增问题。现有测试全部通过。新增逻辑有测试。
- [ ] 推送 tag 后，CI 构建 APK 并发布 release。

## 返工修订（2026-11-14）

验收反馈：交付物把项目拆成多层页面，割裂。发送消息后没有任何反馈。会话加载很慢。

### 修订后的需求

- R2'（替换 R2）：没有项目页。用户从主页的项目或工作区进入，落点是原编辑器页。
- R3'：agent 全部嵌入原编辑器页。应用里只有一个编辑器页。
- R4'：侧边栏顶部分段「文件 | 会话」。文件分段是原文件树，不改。会话分段是会话列表。
- R5'：窄屏和中屏用分段「编辑器 | Agent」切换主体。
- R6'：宽屏三栏。左侧侧边栏，中间编辑器，右侧 Agent 面板。Agent 面板可收起。
- R12 反馈：发送后 100 毫秒内，界面出现用户消息、进度条和停止按钮。
- R13 模型选择：输入卡片工具行始终显示模型选择。
- R14 性能：会话列表、会话打开、发送都不等网络。预算见 design.md §11.7。
- R15 原逻辑不变：除新增的 agent 入口外，主页和编辑器页的行为与改动前一致。
- R16 并行：一个会话对应一个 agent。多个会话可以同时运行。切换会话不停止其他会话。
- R17 同文件保护：同一个文件同一时刻只允许一个会话写。
- R18 检查流程：实现、交叉检查、真机全流程检查、大脑复查、UI/UX 检查，按顺序全部通过才合并。

### 延后（下一步，先出设计）

- 每个会话一个分支。桌面用 git worktree。手机用写时复制的叠加层。合并前检查。
- 设计由 pi-D 在 `research/G-agent-isolation.md` 给出。

### 修订后的验收标准

- [ ] 从主页打开项目，路由栈是「主页 + 编辑器页」。返回一次回到主页。
- [ ] 发送消息、切换会话、新建会话都不产生路由跳转。
- [ ] 发送后 100 毫秒内出现用户消息、进度条、停止按钮。
- [ ] 输入卡片工具行有：加号、权限、模型、推理强度（模型支持时）、发送。
- [ ] 模型列表为空或失败时，模型选择显示「默认模型」，不消失。
- [ ] 断网时，打开已有会话在 300 毫秒内显示历史。
- [ ] 两个会话同时运行。切换会话后，原会话继续运行。
- [ ] 会话列表显示每个会话的状态：运行中、排队、待确认、失败、已完成未读。
- [ ] 两个会话写同一文件时，后到的会话收到冲突提示，文件不被覆盖。
- [ ] 离线产品（offlineOnly）的编辑器页与改动前一致，没有新增控件。
- [ ] 旧测试不改断言、不改步骤，全部通过。仅允许 `editor_run_target_test` 的 3 个既有失败。
- [ ] `check/` 目录有交叉检查报告和真机全流程报告，含截图。

## 第四轮补充（2026-11-14）

真机验收暴露三个可用性问题：TLS 错误缺少细节、窄屏顶栏标题太窄、手机工具行留白。

### 第四轮新增需求

- R19 错误详情与连接诊断：AI 请求失败后显示主机名与失败步骤。详情区支持等宽复制。
- R19a 错误脱敏：详情和诊断结果不得包含 `Authorization` 头、令牌、正文或查询串。
- R19b 时间文案边界：仅在证书过期或未生效时，才提示用户检查设备时间。
- R19c 按需诊断：`dns`、`connect`、`tls`、`timeout` 四类失败显示「诊断连接」按钮。用户点击后才探测，不自动诊断。
- R20 窄屏自适应：宽屏才显示顶栏机器人图标。窄屏与中屏把未读或失败角标挂在「Agent」分段上。
- R20a 工具行排版：输入卡片工具行按实际可用宽度决定文字显隐，收起顺序为推理强度、权限、模型名。

### 第四轮验收标准

- [ ] 服务器请求失败后，错误卡片显示主机名与失败步骤。「详情」支持选中和带时间戳复制。
- [ ] 将测试令牌注入配置后，错误详情和诊断输出均不包含该令牌。
- [ ] 点击「诊断连接」仅探测当前 API 服务器，分步报告 DNS、TCP 与 TLS 结果及结论。
- [ ] 宽 424 下开启 Agent 后，顶栏标题宽度与关闭前相同，且分段按钮不小于 44×44。
- [ ] 宽 424 缩放 1.0 下工具行权限显示「每次询问」，宽 360 缩放 1.3 下不溢出。
