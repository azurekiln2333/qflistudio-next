# 设计（Pi C）

## 大脑给定的边界

- 归属：工具页框架、工具注册表、可见范围判断、显示密度、重复工具合并、第 1 批工具。
- 契约见父任务 `design.md` 3.2 和 3.3。
- 注册表按批拆分：`batch1`、`batch2`、`batch3` 各一个注册文件。总注册表拼接三批。这样 C、D、B 不改同一个文件。
- 可见范围是工具条目的属性，不是页面里的条件判断。工具页按属性过滤。
- 移植来的工具放在哪个仓库由你决定。决定标准：子项目里必须看不到这些工具；工具页 UI 必须对子项目可用。把决定和理由写进契约。
- 「是否为主程序」的判断放在新文件里。判断依据用现有的应用配置信息。不改 `studio_profile.dart` 和 `main.dart`。
- 显示密度的持久化沿用项目现有的本地设置方式。
- 用户原话：「工具页 把D:\MyOtherNewProj\netrix 里面所有工具合并进来 记住是所有 包括逻辑 紧密显示和宽松显示 全部1:1照搬 现有工具如果重复就合并保留」「工具页移植过来那些工具只能出现在qflistudio主程序 不能出现在子项目 做好显隐性 但是UI必须搬过来」。

## 与 Pi D 的配合

- Pi D 写清单时会同时列出本项目的现有工具，并标出疑似重复。重复的最终判定由你做。
- 清单出现之前，你先做契约、骨架、工具页框架。
- 清单出现之后，你移植第 1 批。
