1. 用户创建审核服务的发布仓库。
2. 用户推送已提交的审核代码。
3. 等待流水线测试并构建镜像。
4. 部署审核服务。
5. 检查审核健康与变体拦截。
6. 暂停 QFLI 更新与业务写入。
7. 备份数据库和数据目录。
8. 配置 QFLI 审核凭据。
9. 执行 QFLI 数据库迁移。
10. 更新 QFLI 镜像和 nginx。
11. 执行严格冒烟测试。
12. 记录镜像摘要与测试结果。

必须先部署审核服务。
审核不可用时，QFLI 拒绝发布。
此时接口返回 `503 moderation.unavailable`。
不要通过关闭审核来恢复发布。

## 3. 审核镜像与流水线

已有审核实例时，先执行第 7 节。
完成备份后再返回本节。
首次上线按章节顺序执行。

审核仓库保留根 `.cnb.yml`。
CNB 流水线继续发布 CNB 镜像。
GitHub Actions 另行发布 GHCR 镜像。
两者使用同一套测试与 lint。
GitHub 的 push 和 PR 都跑检查。
main 和版本标签通过检查后才发布。
拉取请求只测试。
拉取请求不登录镜像仓库。
版本预发布标签不更新 `latest`。
流水线不会连接生产服务器。

GitHub 发布使用仓库内置令牌。
发布作业需要 `packages:write` 权限。
用户须先允许仓库创建 GHCR 包。

用户须选择本次通过测试的标签。

main 和正式版本都会更新该标签。
人工升级与回滚使用固定摘要。
固定摘要不会自动跟随新镜像。
私有镜像须先完成服务器登录。
登录时使用标准输入传入密码。

## 4. 签发两个应用的凭据

为 QFLI 和网关分配不同 appId。
每个应用分别持有 API 密钥和管理密钥。
下列命令创建四个随机密钥。
每个密钥包含 64 个十六进制字符。
命令仅写文件，不打印密钥。
重复执行会拒绝覆盖原文件。

```bash
python3 - <<'PY'
import json
import os
import secrets
from pathlib import Path

root = Path('/etc/azurekiln')
paths = [root / 'moderation.env', root / 'qfli-moderation.env', root / 'gateway-moderation.env']
if any(path.exists() for path in paths):
    raise SystemExit('Credential files already exist; preserve them and use an explicit rotation plan')
apps = [{"appId": app, "apiKey": secrets.token_hex(32), "adminKey": secrets.token_hex(32)}
        for app in ('qflistudio', 'gateway')]
content = ["MODERATION_APPS_JSON='" + json.dumps(apps, separators=(',', ':')) + "'\n"]
for app in apps:
    content.append('\n'.join([
        'MODERATION_BASE_URL=http://127.0.0.1:4310',
        'MODERATION_APP_ID=' + app['appId'],
        'MODERATION_API_KEY=' + app['apiKey'],
        'MODERATION_ADMIN_KEY=' + app['adminKey'],
        'MODERATION_TIMEOUT_MS=3000', '']))
for path, text in zip(paths, content):
    fd = os.open(path, os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600)
    with os.fdopen(fd, 'w') as file:
        file.write(text)
PY
```

将网关凭据通过受控通道交给网关运维。
网关须配置 `MODERATION_APP_ID=gateway`。
网关跨主机时须更换审核地址。
跨主机地址使用受限 HTTPS 反代。
不要将管理密钥放入 App 或网页。
不要提交这些环境文件。

## 6. 配置受限反代

同机 QFLI 使用 loopback 审核地址。
跨主机网关使用专用 HTTPS 域名。
先配置域名和有效证书。
再将网关的境内出口 IP 加入白名单。

```nginx
# Replace the hostname, certificate paths, and gateway egress IP before use.
server {
    listen 443 ssl;
    server_name moderation.example.cn;
    ssl_certificate /etc/nginx/tls/moderation/fullchain.pem;
    ssl_certificate_key /etc/nginx/tls/moderation/privkey.pem;

    allow 192.0.2.10; # Replace with the real domestic gateway egress IP.
    deny all;

    location / {
        proxy_pass http://127.0.0.1:4310;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Real-Port $remote_port;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 3s;
        proxy_read_timeout 10s;
    }
}
```

示例 IP 和域名不能直接用于生产。
不要使用 `curl -k`。
不要关闭 Node 的证书检查。

QFLI 的 nginx 示例位于此路径。

```text
docs/deployment/nginx.conf.example
```

在 `/api/` 和终端代理中覆盖这两个头。
不要沿用客户端传入的值。
不要将 `X-Forwarded-For` 当成可信地址。

```nginx
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Real-Port $remote_port;
proxy_set_header X-Forwarded-Proto $scheme;
```

```bash
nginx -t
systemctl reload nginx
```

## 7. 暂停写入并备份

已完成本节时，不要重复执行。
后续步骤沿用原 `BACKUP` 目录。

先让业务进入维护窗口。
暂停外部写入入口。
暂停业务 watchtower。
不要停止独立终端栈的更新服务。
下列命令要求现有 QFLI 部署目录。

```bash
read -r -p 'QFLI 部署绝对目录: ' QFLI_DIR
test "${QFLI_DIR#/}" != "$QFLI_DIR"
test -f "$QFLI_DIR/docker-compose.yaml"
test -f "$QFLI_DIR/.env"
cd "$QFLI_DIR"
BACKUP=/var/backups/azurekiln/$(date -u +%Y%m%dT%H%M%SZ)
install -d -m 700 "$BACKUP"
docker compose stop watchtower
CID=$(docker compose ps -q server)
if [ -n "$CID" ]; then docker inspect --format '{{.Image}}' "$CID" > "$BACKUP/qfli.image-id"; fi
docker compose stop server
cp -p .env docker-compose.yaml "$BACKUP/"
tar -cpf "$BACKUP/qfli-data.tar" -C "$QFLI_DIR" data
cp -p /etc/azurekiln/moderation.env /etc/azurekiln/moderation.image.env "$BACKUP/"
cp -p /opt/azurekiln-moderation/compose.yaml "$BACKUP/moderation.compose.yaml"
```

MySQL 部署须备份 MySQL 数据库。
先配置受保护的登录凭据。
密码由交互提示收取。
数据库名须与业务环境一致。

```bash
mysql_config_editor set --login-path=qfli-backup --host=127.0.0.1 --user=qfli --password
read -r -p 'QFLI 当前 MySQL 数据库名: ' MYSQL_DATABASE
mysqldump --login-path=qfli-backup --single-transaction --no-tablespaces --hex-blob "$MYSQL_DATABASE" > "$BACKUP/qfli.sql"
test -s "$BACKUP/qfli.sql"
```

SQLite 部署跳过 MySQL 命令。
停服后的数据归档包含 SQLite 文件。
不要单独复制仍在写入的 SQLite 主文件。
WAL 中可能仍有未合并数据。

审核升级前也须备份完整卷。
首次部署可在空库迁移后备份。

```bash
cd /opt/azurekiln-moderation
MODERATION_SERVICES=$(docker compose --env-file /etc/azurekiln/moderation.env --env-file /etc/azurekiln/moderation.image.env config --services)
if python3 -c 'import sys; sys.exit("watchtower" not in sys.stdin.read().splitlines())' <<< "$MODERATION_SERVICES"; then
  docker compose --env-file /etc/azurekiln/moderation.env --env-file /etc/azurekiln/moderation.image.env stop watchtower
fi
MODERATION_CID=$(docker compose --env-file /etc/azurekiln/moderation.env --env-file /etc/azurekiln/moderation.image.env ps -q moderation)
test -n "$MODERATION_CID"
MODERATION_VOLUME=$(docker inspect --format '{{range .Mounts}}{{if eq .Destination "/app/var"}}{{.Name}}{{end}}{{end}}' "$MODERATION_CID")
test -n "$MODERATION_VOLUME"
docker inspect --format '{{.Image}}' "$MODERATION_CID" > "$BACKUP/moderation.image-id"
MODERATION_BACKUP_IMAGE=$(cat "$BACKUP/moderation.image-id")
docker image save "$MODERATION_BACKUP_IMAGE" > "$BACKUP/moderation.image.tar"
docker compose --env-file /etc/azurekiln/moderation.env --env-file /etc/azurekiln/moderation.image.env stop moderation
docker run --rm --user 0:0 \
  --mount type=volume,src="$MODERATION_VOLUME",dst=/source,readonly \
  --mount type=bind,src="$BACKUP",dst=/backup \
  --entrypoint tar "$MODERATION_BACKUP_IMAGE" -cpf /backup/moderation-data.tar -C /source .
docker compose --env-file /etc/azurekiln/moderation.env --env-file /etc/azurekiln/moderation.image.env up -d --wait --wait-timeout 90 --no-build moderation
```

备份后保持审核 Watchtower 停止。
验收通过后再决定是否恢复更新。
保存的镜像归档供回滚使用。

备份不得离开境内基础设施。
备份须遵守同样的 365 天保留口径。
恢复后须确认留存清理完成。
不要保留失管的历史快照。

## 8. 配置 QFLI

保留现有网关、终端和数据库配置。
QFLI 新增下列环境变量。

| 变量 | 本次配置 |
| --- | --- |
| `MODERATION_BASE_URL` | 同机为 `http://127.0.0.1:4310` |
| `MODERATION_APP_ID` | `qflistudio` |
| `MODERATION_API_KEY` | QFLI 专用 API 密钥 |
| `MODERATION_ADMIN_KEY` | QFLI 专用管理密钥 |
| `MODERATION_TIMEOUT_MS` | `3000`，允许 `500..30000` |
| `QFLI_MODERATION_SUBJECT_SALT` | 至少 16 位的随机密钥，用于给审核侧的用户标识生成不可逆假名 |
| `PUBLISH_RATE_PER_MINUTE` | `3` |
| `PUBLISH_RATE_PER_DAY` | `20` |
| `COMMENT_RATE_PER_MINUTE` | `10` |
| `COMMENT_RATE_PER_DAY` | `100` |

下列命令合并审核环境文件。
它保留其余环境变量。
它不会打印密钥。

```bash
export QFLI_DIR
python3 - <<'PY'
import os
from pathlib import Path

path = Path(os.environ['QFLI_DIR']) / '.env'
incoming = Path('/etc/azurekiln/qfli-moderation.env').read_text().splitlines()
incoming += ['PUBLISH_RATE_PER_MINUTE=3', 'PUBLISH_RATE_PER_DAY=20',
             'COMMENT_RATE_PER_MINUTE=10', 'COMMENT_RATE_PER_DAY=100']
keys = {line.split('=', 1)[0] for line in incoming if '=' in line}
lines = [line for line in path.read_text().splitlines() if line.split('=', 1)[0] not in keys]
temporary = path.with_name('.env.compliance.tmp')
with temporary.open('x') as file:
    os.chmod(temporary, 0o600)
    file.write('\n'.join(lines + incoming) + '\n')
temporary.replace(path)
PY
```

检查下列既有环境变量。

- `QFLI_JWT_SECRET` 至少包含 32 字符。
- `QFLI_AUDIT_SALT` 使用独立随机值。
- `AZK_OAUTH2_BASE_URL` 指向现有网关。
- `AZK_OAUTH2_CLIENT_ID` 以 `qfli` 开头。
- `AZK_OAUTH2_CLIENT_SECRET` 使用现有凭据。
- `AZK_OAUTH2_ERASE_SCOPE` 为 `qfli_account_erase`。
- `PUBLIC_BASE_URL` 为正式 HTTPS 地址。
- `QFLI_AI_BASE_URL` 只指向 DeepSeek 官方接口。

用户须在网关后台授予注销 scope。
未授权时，网关会返回 403。
该结果不能视为注销成功。
保持 TLS 证书检查开启。

## 9. 更新 QFLI 并迁移数据库

本机只验证 SQLite。
运维须记录生产数据库驱动与迁移结果。
旧 ID 迁移可能重命名数据目录。
因此数据库与数据目录须成对备份。

冒烟通过后，将镜像摘要写入 `.env`。
不要只保留当前 shell 的变量。
下列命令保留其余配置。

```bash
python3 - <<'PY'
import os
from pathlib import Path
path = Path(os.environ['QFLI_DIR']) / '.env'
lines = [line for line in path.read_text().splitlines() if not line.startswith('QFLI_SERVER_IMAGE=')]
temporary = path.with_name('.env.image.tmp')
with temporary.open('x') as file:
    os.chmod(temporary, 0o600)
    file.write('\n'.join(lines + ['QFLI_SERVER_IMAGE=' + os.environ['QFLI_SERVER_IMAGE']]) + '\n')
temporary.replace(path)
PY
```

固定摘要后保持 watchtower 暂停。
下次升级须重复备份和验收步骤。

## 10. 冒烟测试

在可信运维终端使用本仓库脚本。
凭据只能通过环境变量传入。
脚本不打印令牌或响应原文。
脚本拒绝 HTTP 重定向。
脚本保持正常 TLS 证书检查。

审核服务就绪后先执行此命令。
此命令会跳过 QFLI 账号检查。

```bash
set -a
. /etc/azurekiln/qfli-moderation.env
set +a
node /path/to/qflistudio/scripts/compliance/smoke.mjs --moderation "$MODERATION_BASE_URL"
```

为完整验收准备两个专用测试会话。
一个会话没有已验证手机号。
另一个会话已完成手机号验证。
令牌须由测试环境的正式登录流程取得。
不要在生产库伪造用户或会话。
不要使用普通用户的令牌。

```bash
read -r -s -p '未实名测试令牌: ' SMOKE_UNVERIFIED_TOKEN; printf '\n'
read -r -s -p '已实名测试令牌: ' SMOKE_RATE_TOKEN; printf '\n'
export SMOKE_UNVERIFIED_TOKEN SMOKE_RATE_TOKEN
node /path/to/qflistudio/scripts/compliance/smoke.mjs \
  --qfli https://qfli.suanxiwanjie.cn \
  --moderation "$MODERATION_BASE_URL" \
  --strict --allow-rate --max-rate-requests 5
unset SMOKE_UNVERIFIED_TOKEN SMOKE_RATE_TOKEN
```

严格模式要求全部检查通过。
跳过账号检查也会导致失败。
`--allow-rate` 明确允许消耗测试账号配额。
默认最多提交五次阻断测试内容。
默认分钟限额为三次。
已消耗的配额可能让 429 更早出现。
分钟切换可能使请求预算不足。
限额调整后须同步请求预算。
脚本先确认审核服务会阻断测试词。
意外发布成功时，脚本立即停止该检查。
管理员须删除该测试内容并留痕。

检查项目如下。

- QFLI 与审核服务健康。
- 大小写、全角和插入字符拦截。
- 繁简和违禁品变体拦截。
- 五类联网服务的未实名 403。
- 请求路径的大小写与查询参数变体。
- 发布限流 429 与 `retryAfter`。

生产若无法取得未实名测试会话，须记录缺项。
不要用无效令牌冒充未实名账号。
无效令牌的 401 不能代替实名 403。

本机双进程测试使用临时数据库。
它不读取生产 `.env`。
它使用 vendored SDK。

```powershell
node scripts/compliance/local-e2e.mjs --moderation-repo D:/MyNewProjects/azurekiln-moderation
```

## 11. 回滚

先暂停写入与 watchtower。
再停止 QFLI 和审核服务。
先保存失败现场的数据库与日志。
不要让旧镜像直接使用未知的新表结构。

先选择同一时间点的完整备份。
下列命令保留失败数据。

```bash
read -r -p '完整备份绝对目录: ' BACKUP
test "${BACKUP#/var/backups/azurekiln/}" != "$BACKUP"
test -s "$BACKUP/qfli.image-id"
test -s "$BACKUP/moderation.image-id"
cd "$QFLI_DIR"
docker compose stop watchtower server
cd /opt/azurekiln-moderation
docker compose --env-file /etc/azurekiln/moderation.env --env-file /etc/azurekiln/moderation.image.env stop watchtower moderation
```

下列流程恢复成对备份。
MySQL 须恢复到新的空数据库。
下列命令需要 DBA 登录凭据。
DBA 还须授予原业务账号访问权限。

```bash
read -r -p '新建的回滚数据库名: ' QFLI_ROLLBACK_DB
[[ "$QFLI_ROLLBACK_DB" =~ ^[A-Za-z0-9_]+$ ]]
mysql --login-path=qfli-admin -e "CREATE DATABASE \`$QFLI_ROLLBACK_DB\` CHARACTER SET utf8mb4"
mysql --login-path=qfli-admin "$QFLI_ROLLBACK_DB" < "$BACKUP/qfli.sql"
export QFLI_ROLLBACK_DB
```

恢复数据库时，也须恢复数据目录。
SQLite 须跳过上面的 MySQL 命令。
SQLite 直接恢复完整数据目录。

```bash
RESTORE_DIR="$QFLI_DIR/.restore-$(date -u +%Y%m%dT%H%M%SZ)"
install -d -m 700 "$RESTORE_DIR"
tar -xpf "$BACKUP/qfli-data.tar" -C "$RESTORE_DIR"
test -d "$RESTORE_DIR/data"
mv "$QFLI_DIR/data" "$RESTORE_DIR/data.failed"
mv "$RESTORE_DIR/data" "$QFLI_DIR/data"
```

审核库也应恢复到新的空卷。
保留失败卷，直至核定恢复结果。

```bash
cd /opt/azurekiln-moderation
ROLLBACK_VOLUME=azurekiln-moderation-rollback-$(date -u +%Y%m%dT%H%M%SZ)
docker volume create "$ROLLBACK_VOLUME"
MODERATION_ROLLBACK_IMAGE=$(cat "$BACKUP/moderation.image-id")
docker image load --input "$BACKUP/moderation.image.tar"
docker run --rm --user 0:0 \
  --mount type=volume,src="$ROLLBACK_VOLUME",dst=/restore \
  --mount type=bind,src="$BACKUP",dst=/backup,readonly \
  --entrypoint tar "$MODERATION_ROLLBACK_IMAGE" -xpf /backup/moderation-data.tar -C /restore
export BACKUP QFLI_DIR ROLLBACK_VOLUME
python3 - <<'PY'
import os
from pathlib import Path

backup = Path(os.environ['BACKUP'])
compose = (backup / 'moderation.compose.yaml').read_text()
known_names = [
    '    name: azurekiln-moderation-data',
    '    name: ${MODERATION_DATA_VOLUME:-${COMPOSE_PROJECT_NAME:-azurekiln-moderation}-data}',
]
matches = [name for name in known_names if compose.count(name) == 1]
if len(matches) != 1:
    raise SystemExit('Inspect the saved volume name before restoring a customized compose file')
Path('/opt/azurekiln-moderation/compose.rollback.yaml').write_text(
    compose.replace(matches[0], '    name: ' + os.environ['ROLLBACK_VOLUME']))
for name in ('moderation.env', 'moderation.image.env'):
    target = Path('/etc/azurekiln') / name
    target.write_bytes((backup / name).read_bytes())
    target.chmod(0o600)
moderation_env = Path('/etc/azurekiln/moderation.image.env')
moderation_updates = {
    'MODERATION_IMAGE': (backup / 'moderation.image-id').read_text().strip(),
    'MODERATION_DATA_VOLUME': os.environ['ROLLBACK_VOLUME'],
}
moderation_lines = [line for line in moderation_env.read_text().splitlines()
                    if line.split('=', 1)[0] not in moderation_updates]
moderation_env.write_text('\n'.join(moderation_lines + [
    key + '=' + value for key, value in moderation_updates.items()]) + '\n')
path = Path(os.environ['QFLI_DIR']) / '.env'
lines = (backup / '.env').read_text().splitlines()
updates = {'QFLI_SERVER_IMAGE': (backup / 'qfli.image-id').read_text().strip()}
if os.environ.get('QFLI_ROLLBACK_DB'):
    updates['MYSQL_DATABASE'] = os.environ['QFLI_ROLLBACK_DB']
lines = [line for line in lines if line.split('=', 1)[0] not in updates]
path.write_text('\n'.join(lines + [key + '=' + value for key, value in updates.items()]) + '\n')
path.chmod(0o600)
PY
QFLI_SERVER_IMAGE=$(cat "$BACKUP/qfli.image-id")
export QFLI_SERVER_IMAGE
docker compose -f compose.rollback.yaml --env-file /etc/azurekiln/moderation.env --env-file /etc/azurekiln/moderation.image.env config --quiet
docker compose -f compose.rollback.yaml --env-file /etc/azurekiln/moderation.env --env-file /etc/azurekiln/moderation.image.env up -d --wait --wait-timeout 90 --no-build --pull never moderation
curl --fail --max-time 5 http://127.0.0.1:4310/healthz
cd "$QFLI_DIR"
docker compose config --quiet
docker compose up -d --wait --wait-timeout 90 --no-build --pull never server
```

完整恢复后，固定新的卷配置。
回滚后保持审核 Watchtower 停止。

```bash

```

回滚后也须固定镜像与数据库配置。

记录停服区间与回滚原因。
