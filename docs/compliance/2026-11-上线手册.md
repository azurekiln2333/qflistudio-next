## 1. 上线顺序

1. 用户创建审核服务的 CNB 仓库。
2. 用户推送已提交的审核代码。
3. 等待流水线测试并构建镜像。
4. 部署审核服务。
5. 检查审核健康与变体拦截。
6. 暂停 QFLI 更新与业务写入。
7. 备份数据库和数据目录。
8. 配置 QFLI 审核凭据。
9. 执行 QFLI 数据库迁移。
10. 更新 QFLI 镜像和 nginx。
11. 执行严格冒烟测试。
12. 记录镜像摘要与测试结果。

必须先部署审核服务。
审核不可用时，QFLI 拒绝发布。
此时接口返回 `503 moderation.unavailable`。
不要通过关闭审核来恢复发布。

## 4. 签发两个应用的凭据

为 QFLI 和网关分配不同 appId。
每个应用分别持有 API 密钥和管理密钥。
下列命令创建四个随机密钥。
每个密钥包含 64 个十六进制字符。
命令仅写文件，不打印密钥。
重复执行会拒绝覆盖原文件。

```bash
python3 - <<'PY'
import json
import os
import secrets
from pathlib import Path

root = Path('/etc/azurekiln')
paths = [root / 'moderation.env', root / 'qfli-moderation.env', root / 'gateway-moderation.env']
if any(path.exists() for path in paths):
    raise SystemExit('Credential files already exist; preserve them and use an explicit rotation plan')
apps = [{"appId": app, "apiKey": secrets.token_hex(32), "adminKey": secrets.token_hex(32)}
        for app in ('qflistudio', 'gateway')]
content = ["MODERATION_APPS_JSON='" + json.dumps(apps, separators=(',', ':')) + "'\n"]
for app in apps:
    content.append('\n'.join([
        'MODERATION_BASE_URL=http://127.0.0.1:4310',
        'MODERATION_APP_ID=' + app['appId'],
        'MODERATION_API_KEY=' + app['apiKey'],
        'MODERATION_ADMIN_KEY=' + app['adminKey'],
        'MODERATION_TIMEOUT_MS=3000', '']))
for path, text in zip(paths, content):
    fd = os.open(path, os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600)
    with os.fdopen(fd, 'w') as file:
        file.write(text)
PY
```

将网关凭据通过受控通道交给网关运维。
网关须配置 `MODERATION_APP_ID=gateway`。
网关跨主机时须更换审核地址。
跨主机地址使用受限 HTTPS 反代。
不要将管理密钥放入 App 或网页。
不要提交这些环境文件。

## 6. 配置受限反代

同机 QFLI 使用 loopback 审核地址。
跨主机网关使用专用 HTTPS 域名。
先配置域名和有效证书。
再将网关的境内出口 IP 加入白名单。

```nginx
# Replace the hostname, certificate paths, and gateway egress IP before use.
server {
    listen 443 ssl;
    server_name moderation.example.cn;
    ssl_certificate /etc/nginx/tls/moderation/fullchain.pem;
    ssl_certificate_key /etc/nginx/tls/moderation/privkey.pem;

    allow 192.0.2.10; # Replace with the real domestic gateway egress IP.
    deny all;

    location / {
        proxy_pass http://127.0.0.1:4310;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Real-Port $remote_port;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 3s;
        proxy_read_timeout 10s;
    }
}
```

示例 IP 和域名不能直接用于生产。
不要使用 `curl -k`。
不要关闭 Node 的证书检查。

QFLI 的 nginx 示例位于此路径。

```text
docs/deployment/nginx.conf.example
```

在 `/api/` 和终端代理中覆盖这两个头。
不要沿用客户端传入的值。
不要将 `X-Forwarded-For` 当成可信地址。

```nginx
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Real-Port $remote_port;
proxy_set_header X-Forwarded-Proto $scheme;
```

```bash
nginx -t
systemctl reload nginx
```

## 7. 暂停写入并备份

已完成本节时，不要重复执行。
后续步骤沿用原 `BACKUP` 目录。

先让业务进入维护窗口。
暂停外部写入入口。
暂停业务 watchtower。
不要停止独立终端栈的更新服务。
下列命令要求现有 QFLI 部署目录。

```bash
read -r -p 'QFLI 部署绝对目录: ' QFLI_DIR
test "${QFLI_DIR#/}" != "$QFLI_DIR"
test -f "$QFLI_DIR/docker-compose.yaml"
test -f "$QFLI_DIR/.env"
cd "$QFLI_DIR"
BACKUP=/var/backups/azurekiln/$(date -u +%Y%m%dT%H%M%SZ)

CID=$(docker compose ps -q server)
if [ -n "$CID" ]; then docker inspect --format '{{.Image}}' "$CID" > "$BACKUP/qfli.image-id"; fi
docker compose stop server

tar -cpf "$BACKUP/qfli-data.tar" -C "$QFLI_DIR" data

cp -p /opt/azurekiln-moderation/compose.yaml "$BACKUP/moderation.compose.yaml"
```

MySQL 部署须备份 MySQL 数据库。
先配置受保护的登录凭据。
密码由交互提示收取。

```bash
mysql_config_editor set --login-path=qfli-backup --host=127.0.0.1 --user=qfli --password
read -r -p 'QFLI 当前 MySQL 数据库名: ' MYSQL_DATABASE
mysqldump --login-path=qfli-backup --single-transaction --no-tablespaces --hex-blob "$MYSQL_DATABASE" > "$BACKUP/qfli.sql"
test -s "$BACKUP/qfli.sql"
```

SQLite 部署跳过 MySQL 命令。
停服后的数据归档包含 SQLite 文件。
不要单独复制仍在写入的 SQLite 主文件。
WAL 中可能仍有未合并数据。

审核升级前也须备份完整卷。
首次部署可在空库迁移后备份。

```bash
cd /opt/azurekiln-moderation
MODERATION_CID=$(docker compose --env-file /etc/azurekiln/moderation.image.env ps -q moderation)
test -n "$MODERATION_CID"
docker inspect --format '{{.Image}}' "$MODERATION_CID" > "$BACKUP/moderation.image-id"
MODERATION_BACKUP_IMAGE=$(cat "$BACKUP/moderation.image-id")

docker run --rm --user 0:0 \
  --mount type=volume,src=azurekiln-moderation-data,dst=/source,readonly \
  --mount type=bind,src="$BACKUP",dst=/backup \

```

备份不得离开境内基础设施。

## 8. 配置 QFLI

保留现有网关、终端和数据库配置。
QFLI 新增下列环境变量。

| 变量 | 本次配置 |
| --- | --- |
| `MODERATION_BASE_URL` | 同机为 `http://127.0.0.1:4310` |
| `MODERATION_APP_ID` | `qflistudio` |
| `MODERATION_API_KEY` | QFLI 专用 API 密钥 |
| `MODERATION_ADMIN_KEY` | QFLI 专用管理密钥 |
| `MODERATION_TIMEOUT_MS` | `3000`，允许 `500..30000` |
| `PUBLISH_RATE_PER_MINUTE` | `3` |
| `PUBLISH_RATE_PER_DAY` | `20` |
| `COMMENT_RATE_PER_MINUTE` | `10` |
| `COMMENT_RATE_PER_DAY` | `100` |

下列命令合并审核环境文件。
它保留其余环境变量。
它不会打印密钥。

```bash
export QFLI_DIR
python3 - <<'PY'
import os
from pathlib import Path

path = Path(os.environ['QFLI_DIR']) / '.env'
incoming = Path('/etc/azurekiln/qfli-moderation.env').read_text().splitlines()
incoming += ['PUBLISH_RATE_PER_MINUTE=3', 'PUBLISH_RATE_PER_DAY=20',
             'COMMENT_RATE_PER_MINUTE=10', 'COMMENT_RATE_PER_DAY=100']
keys = {line.split('=', 1)[0] for line in incoming if '=' in line}
lines = [line for line in path.read_text().splitlines() if line.split('=', 1)[0] not in keys]
temporary = path.with_name('.env.compliance.tmp')
with temporary.open('x') as file:
    os.chmod(temporary, 0o600)
    file.write('\n'.join(lines + incoming) + '\n')
temporary.replace(path)
PY
```

检查下列既有环境变量。

- `QFLI_JWT_SECRET` 至少包含 32 字符。
- `QFLI_AUDIT_SALT` 使用独立随机值。
- `AZK_OAUTH2_BASE_URL` 指向现有网关。
- `AZK_OAUTH2_CLIENT_ID` 以 `qfli` 开头。
- `AZK_OAUTH2_CLIENT_SECRET` 使用现有凭据。
- `AZK_OAUTH2_ERASE_SCOPE` 为 `qfli_account_erase`。
- `PUBLIC_BASE_URL` 为正式 HTTPS 地址。
- `QFLI_AI_BASE_URL` 只指向 DeepSeek 官方接口。

用户须在网关后台授予注销 scope。
未授权时，网关会返回 403。
该结果不能视为注销成功。
保持 TLS 证书检查开启。

## 10. 冒烟测试

在可信运维终端使用本仓库脚本。
凭据只能通过环境变量传入。
脚本不打印令牌或响应原文。
脚本拒绝 HTTP 重定向。
脚本保持正常 TLS 证书检查。

审核服务就绪后先执行此命令。
此命令会跳过 QFLI 账号检查。

```bash
set -a
. /etc/azurekiln/qfli-moderation.env
set +a
node /path/to/qflistudio/scripts/compliance/smoke.mjs --moderation "$MODERATION_BASE_URL"
```

为完整验收准备两个专用测试会话。
一个会话没有已验证手机号。
另一个会话已完成手机号验证。
令牌须由测试环境的正式登录流程取得。
不要在生产库伪造用户或会话。
不要使用普通用户的令牌。

```bash
read -r -s -p '未实名测试令牌: ' SMOKE_UNVERIFIED_TOKEN; printf '\n'
read -r -s -p '已实名测试令牌: ' SMOKE_RATE_TOKEN; printf '\n'
export SMOKE_UNVERIFIED_TOKEN SMOKE_RATE_TOKEN
node /path/to/qflistudio/scripts/compliance/smoke.mjs \
  --qfli https://qfli.suanxiwanjie.cn \
  --moderation "$MODERATION_BASE_URL" \
  --strict --allow-rate --max-rate-requests 5
unset SMOKE_UNVERIFIED_TOKEN SMOKE_RATE_TOKEN
```

严格模式要求全部检查通过。
跳过账号检查也会导致失败。
`--allow-rate` 明确允许消耗测试账号配额。
默认最多提交五次阻断测试内容。
默认分钟限额为三次。
已消耗的配额可能让 429 更早出现。
分钟切换可能使请求预算不足。
限额调整后须同步请求预算。
脚本先确认审核服务会阻断测试词。
意外发布成功时，脚本立即停止该检查。
管理员须删除该测试内容并留痕。

检查项目如下。

- QFLI 与审核服务健康。
- 大小写、全角和插入字符拦截。
- 繁简和违禁品变体拦截。
- 五类联网服务的未实名 403。
- 发布限流 429 与 `retryAfter`。

生产若无法取得未实名测试会话，须记录缺项。
不要用无效令牌冒充未实名账号。
无效令牌的 401 不能代替实名 403。

本机双进程测试使用临时数据库。
它不读取生产 `.env`。
它使用 vendored SDK。

```powershell
node scripts/compliance/local-e2e.mjs --moderation-repo D:/MyNewProjects/azurekiln-moderation
```

审核库也应恢复到新的空卷。
保留失败卷，直至核定恢复结果。

```bash

ROLLBACK_VOLUME=azurekiln-moderation-rollback-$(date -u +%Y%m%dT%H%M%SZ)
docker volume create "$ROLLBACK_VOLUME"

  --mount type=volume,src="$ROLLBACK_VOLUME",dst=/restore \
  --mount type=bind,src="$BACKUP",dst=/backup,readonly \
  --entrypoint tar "$MODERATION_ROLLBACK_IMAGE" -xpf /backup/moderation-data.tar -C /restore
export BACKUP QFLI_DIR ROLLBACK_VOLUME
python3 - <<'PY'
import os
from pathlib import Path

backup = Path(os.environ['BACKUP'])
compose = (backup / 'moderation.compose.yaml').read_text()
old_name = '    name: azurekiln-moderation-data'
if compose.count(old_name) != 1:
    raise SystemExit('Inspect the saved volume name before restoring a customized compose file')
Path('/opt/azurekiln-moderation/compose.rollback.yaml').write_text(
    compose.replace(old_name, '    name: ' + os.environ['ROLLBACK_VOLUME']))
for name in ('moderation.env', 'moderation.image.env'):
    target = Path('/etc/azurekiln') / name
    target.write_bytes((backup / name).read_bytes())
    target.chmod(0o600)
Path('/etc/azurekiln/moderation.image.env').write_text(
    'MODERATION_IMAGE=' + (backup / 'moderation.image-id').read_text().strip() + '\n')
path = Path(os.environ['QFLI_DIR']) / '.env'
lines = (backup / '.env').read_text().splitlines()
updates = {'QFLI_SERVER_IMAGE': (backup / 'qfli.image-id').read_text().strip()}
if os.environ.get('QFLI_ROLLBACK_DB'):
    updates['MYSQL_DATABASE'] = os.environ['QFLI_ROLLBACK_DB']
lines = [line for line in lines if line.split('=', 1)[0] not in updates]
path.write_text('\n'.join(lines + [key + '=' + value for key, value in updates.items()]) + '\n')
path.chmod(0o600)
PY
QFLI_SERVER_IMAGE=$(cat "$BACKUP/qfli.image-id")
export QFLI_SERVER_IMAGE
docker compose -f compose.rollback.yaml --env-file /etc/azurekiln/moderation.image.env config --quiet
docker compose -f compose.rollback.yaml --env-file /etc/azurekiln/moderation.image.env up -d --wait --wait-timeout 90 --no-build --pull never moderation
curl --fail --max-time 5 http://127.0.0.1:4310/healthz
cd "$QFLI_DIR"
docker compose config --quiet
docker compose up -d --wait --wait-timeout 90 --no-build --pull never server
```
