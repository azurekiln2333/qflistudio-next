# 启动与渲染改进

## 已修改

1. `runApp` 先提交轻量启动页，三份本地配置在首帧回调后并行加载。
2. 删除固定 900 毫秒启动展示时间。某一份配置加载失败也不会让启动页永久等待。
3. 首页只初始化项目页，教程、讨论和个人页在首次选中后创建，保留后续状态。
4. 应用目录探测复用同一个 Future，首个可用支持目录成功后立即返回；写入探针改为异步。
5. 项目注册表解析和缺失语言元数据回填移到 isolate，反复加载不再追加重复项目。
6. 全局主题使用 MD3 色彩角色，设置页的浅色/深色选择真正连接到 `MaterialApp.themeMode`。
7. Android 启动主题及 NormalTheme、鸿蒙启动窗口及 ArkUI 背景、iOS 启动/主视图采用与 Flutter 一致的系统亮暗背景（亮 `#F8F9FF`，暗 `#111418`）。
8. 补齐 Android 发行版联网权限，以及 macOS 沙箱的网络客户端与本地预览服务权限。

设置读取前只能使用系统外观；如果应用手动外观与系统相反，读取后仍可能出现一次主题切换。引擎冷启动和设备 GPU 初始化也有不可消除的成本，不应仅凭代码修改宣称所有设备“零白屏”。

## 自动验证与真机验收

自动测试覆盖：启动不再等待固定时长、失败容错、懒加载页面、全局主题切换、空列表原生下拉刷新、配置往返、HTML/CSS/JS 高亮、输入快照合并、长行回退、worker 超时退出及查找/折叠。

Android release APK 已构建通过，并检查了 APK 内的联网权限。iOS、macOS、鸿蒙本次仅做代码/资源检查，没有完成对应平台构建或真机启动性能验收。

界面预览可通过 `tool/preview_test.dart` 生成到 `docs/previews/`。预览用于检查布局、颜色和文字可读性，不是设备性能跑分。

真机检查应使用 profile 或 release 构建，分别记录冷启动、热启动和恢复前台；debug 模式的 JIT 和调试服务开销不能当作发行版指标。

```powershell
flutter run --profile -d <设备ID>
```

建议验收场景：

| 场景 | 检查 |
| --- | --- |
| 断网冷启动 | 能进入本地项目页，不等社区/账号接口 |
| 系统浅色 / 深色 | 原生窗口到 Flutter 首帧的背景衔接 |
| 手动设置与系统外观不同 | 是否仅有一次可接受的主题切换 |
| 100 个项目 | 项目列表首屏、下拉刷新和重复记录 |
| 普通 HTML，含 style/script | 关键字/属性有颜色，连续输入与滚动流畅 |
| 100–250 KB HTML/CSS | 在 DevTools 查看 UI/raster 帧耗时和输入延迟 |
| 超长压缩行 / 超出高亮限制 | 正常退回纯文本，仍能编辑和保存 |
| 快速切换文件 / 退出编辑器 | 后台任务被释放，无过期回调异常 |

60 Hz 屏幕的单帧预算约为 16.7 毫秒；记录超预算帧及输入延迟，比较同一设备、同一文件、相同构建模式的前后数据。本次没有真机首帧时长或帧率数据，不能把模拟慢解析测试当作真机性能提升百分比。
